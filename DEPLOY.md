# The Signal — build & deploy

## Build (regenerate the whole site)
From `C:\Dev\SensaLab-Newsletter-Bot`, run in this order:

```
python build_og.py        # og.jpg + favicons  (run once, or when the OG art changes)
python build_articles.py  # 12 article pages
python build_kits.py      # 4 free-kit pages
python build_blog_b.py    # home
python build_seo.py       # sitemap.xml, robots.txt, llms.txt, feed.xml, 404.html, privacy.html + OneDrive sync
```

`signal_content.py` is the data hub. It pulls editorial copy from `signal_articles.py`
(auto-generated by the 5-agent editorial workflow — regenerate with `parse_editorial.py`
if that workflow is re-run), curates one image per story, and writes optimized, de-duplicated
assets to `blog/img/` and the Apparat fonts to `blog/fonts/`. Everything the pages reference
is inside `blog/` (self-contained folder), so the deploy target is just the `blog/` directory.

Preview locally: `cd blog && python -m http.server 8090` → http://127.0.0.1:8090

## Deploy
The site is a static folder (`blog/`). Two options:

1. **Netlify Drop (fastest bootstrap):** drag the `blog/` folder onto https://app.netlify.com/drop
   → live at `your-site.netlify.app` in ~30s. No CLI, no token.
2. **GitHub → Netlify (self-publishing pipeline):** push this repo, connect it to Netlify,
   set publish directory to `blog/`. Every push redeploys. The Python engine can then push a
   new edition and the blog publishes itself.

Custom domain later: `signal.sensalab.io` (CNAME to the Netlify site).

## Forms (lead capture) — IMPORTANT
The subscribe form, the free-kit modal, the in-article capture and the kit pages all use
**Netlify Forms**: `name="signal-subscribe"` / `name="signal-kit"`, `data-netlify="true"`,
a hidden `form-name`, and a honeypot `bot-field`. Submissions post via AJAX to `/`.

- Capture is REAL only once the site is deployed on **Netlify** (Netlify detects the forms at
  deploy and stores every submission under Forms in the dashboard). On localhost/file:// the
  JS shows an honest success state for preview but nothing is stored.
- After first deploy: in Netlify → Forms, add an email notification (or a webhook to Make /
  MailerLite) so new subscribers/kit requests reach hello@sensalab.io and the tools.
- If you later prefer MailerLite/Brevo double opt-in, swap the form `action`/handler for the
  provider's embedded endpoint; the markup and success states already exist.
